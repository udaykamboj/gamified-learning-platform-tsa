# CLI Reference

Complete reference for all StarLab CLI commands. The CLI is published as `starlab` on npm and is typically run via `npx starlab@latest`.

## Setup and Configuration

### `starlab setup`

Run the interactive setup wizard. This command generates `docker-compose.yml`, `.env`, `starlab.config.json`, and nginx or Caddy configuration files based on your choices.

```bash
starlab setup
```

Flags: `--ci`, `--name`, `--domain`, `--port`, `--admin-email`, `--admin-password`, `--channel <stable|dev>`, `--no-start`.

You can re-run this command at any time to reconfigure your instance. Existing configuration will be preserved as defaults in the prompts.

### `starlab config`

View the current configuration.

```bash
starlab config
```

### `starlab env`

Interactively edit environment variables in your `.env` file (Domain & Hosting, Database & Redis, Security, AI, Email (Resend), S3 Storage, OAuth).

```bash
starlab env
```

<Callout type="info">
The `env` command edits a curated set of variables only. SMTP credentials (`STARLAB_SMTP_*`) are not editable through this command — edit `.env` directly if you need them.
</Callout>

## Service Management

### `starlab start`

Start all StarLab services. On first run, this pulls the required Docker images before starting containers.

```bash
starlab start
```

### `starlab stop`

Stop all running StarLab services. Data is preserved in Docker volumes.

```bash
starlab stop
```

### `starlab status`

Show the status of each StarLab service.

```bash
starlab status
```

### `starlab logs`

Stream container logs for all services.

```bash
starlab logs
```

### `starlab update`

Update StarLab to the latest release or a specific version. Pulls the target image, rewrites `docker-compose.yml`, restarts services, and prompts for database migrations.

```bash
starlab update
starlab update --version 1.4.2
starlab update --migrate       # auto-apply migrations
starlab update --no-migrate    # skip migrations
```

### `starlab dev`

Start a full development environment (PostgreSQL + Redis in Docker, API + web + collab run locally).

```bash
starlab dev
```

## Diagnostics

### `starlab doctor`

Run diagnostics on your StarLab installation. Checks Docker availability, container health, port conflicts, DNS resolution, and disk space.

```bash
starlab doctor
```

### `starlab health`

Run the CLI's health checks (PostgreSQL connection, Redis ping, HTTP health endpoint, disk, resources).

```bash
starlab health
```

### `starlab shell`

Open an interactive shell inside a running container for debugging.

```bash
starlab shell
```

## Infrastructure

### `starlab deployments`

Manage deployments and scale memory limits for your StarLab containers.

```bash
starlab deployments
```

## Backup and Restore

### `starlab backup`

Create a PostgreSQL dump archive of your instance's database (plus a copy of `.env`). Archives are written to `<installDir>/backups/`.

```bash
starlab backup
```

### `starlab restore`

Restore a database from a backup archive.

```bash
starlab restore <path/to/starlab-backup-<timestamp>.tar.gz>
```
